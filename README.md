# HelloWorldAnnotationProcessor
JavaでHelloWorldと表示するだけのアノテーションとアノテーションプロセッサです。 Javaのアノテーションプロセッサは仕様によりソースコードやリソースの生成しかできず、コンパイル中のソースコードの中身を直接編集することはできません。そこで実行中のコンパイラのAST（抽象構文木）に直接手を入れる方法でロジックを書き換えています。凝ったアノテーションプロセッサを作りたい方は参考にしてください。

## プロジェクトについて
以下のサブプロジェクトに分かれています。
- **lib**: アノテーションプロセッサ本体
- **examples**: サンプルコード

## 使用方法
### 設定
ご自分のプロジェクトにサブプロジェクトlibを追加し、build.gradleに以下の記述を追加します。
``` build.gradle

dependencies
{
    （中略）
    
    implementation project(':lib')
    annotationProcessor project(':lib')
}

tasks.withType(JavaCompile)
{
    （中略）
    
    options.fork = true
    options.forkOptions.jvmArgs += '--add-exports=jdk.compiler/com.sun.tools.javac.processing=ALL-UNNAMED'
    options.forkOptions.jvmArgs += '--add-exports=jdk.compiler/com.sun.tools.javac.util=ALL-UNNAMED'
    options.forkOptions.jvmArgs += '--add-exports=jdk.compiler/com.sun.tools.javac.tree=ALL-UNNAMED'
    
    options.compilerArgs += '-Averbose=true'  //  詳細メッセージを表示する場合。普段このオプションは指定しなくていい
}
```

### アノテーションの使用
ご自分のプログラムのメソッドに以下のアノテーションをつけてコンパイルしてください。
- @HelloWorld

以下はサンプルプログラムです。
``` App1.java
import io.github.kurokawa_kun.annotation.HelloWorld;

public class App1
{
    @HelloWorld
    public static void main(String[] args)
    {
    }
}
```

## 補足 - コンパイルについて
Javaのコンパイラは以下のステップでバイトコードの生成を行っています。
1. AST（抽象構文木）の構築
2. アノテーション処理
3. アトリビュート（属性付与）
4. フロー分析
5. コード生成

### 1. AST（抽象構文木）の構築
ソースコードをツリー構造のデータ（AST）に変換します。ソースコードを`if`, `class`, 変数名, `+`などの最小単位に分解し（レキシカル分析）、ASTの形に組み立てます（構文解析）。
この段階では構文が正しいかだけをチェックしており、その変数が本当に存在するか型が合っているかなどは見ていません。

### 2. アノテーション処理
コード内に書かれたアノテーション（`@Override`や`@Setter`など）を検出して処理します。Javacの中に組み込まれた、または外部から指定されたアノテーションプロセッサを呼び出します。
この段階で新しいソースコードが生成された場合、コンパイラは「1.ASTの構築」に戻って新ファイルをもう一度解析し直します。

### 3. アトリビュート（属性付与）
構文木のそれぞれのパーツに属性を付与します。具体的には、<br>
3.1. シンボル解決: 例えばStringという文字列が「どのパッケージのどのクラスのことを指しているのか」を確定させます。<br>
3.2. 型チェック: 例えば`int a = "hello";`のように右辺と左辺の型が矛盾していないかを厳密に検証します。<br>
3.3. 定数畳み込み: 例えば`1 + 2`のような式を`3`という結果に置き換えて木を最適化します。<br>

### 4. フロー分析
プログラムの制御フロー・データフローに問題がないかを論理的にチェックします。具体的には、<br>
4.1. 到達可能性チェック: 絶対実行されないコード、例えば `return;` の後ろに書かれたコードなどがないかを調べます。<br>
4.2. 初期化チェック: ローカル変数が初期化される前に使われていないかをすべての分岐パターンにおいて検証します。<br>
4.3. 例外チェック: チェック例外（キャッチまたはthrowsが必要な例外）が正しく処理されているかを追跡します。<br>
4.4. finalチェック: `final` がついた変数が、2回以上書き換えられていないかを保証します。<br>

### 5. コード生成
ASTの木構造を上から順にスキャンし、バイトコード（.class）に変換してファイルに出力します。

## 補足 - アノテーションプロセッサについて
アノテーションプロセッサが行うことは主に以下の3つです。
1. ボイラープレートコードの自動生成
2. バリデーション / 静的解析
3. 設定ファイルやメタデータの自動生成

Javaの仕様により、アノテーションプロセッサはコンパイル中のソースコードを動的に書き替えることはできません。そこで、本プログラムではコンパイラが保持しているASTを取得し動的に書き換える方法をとっています。
